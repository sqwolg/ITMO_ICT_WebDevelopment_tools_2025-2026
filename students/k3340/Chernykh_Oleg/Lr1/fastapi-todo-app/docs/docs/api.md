# API

## Пользователи

| Метод | Путь | Назначение | Авторизация |
| --- | --- | --- | --- |
| `POST` | `/users/` | Создать пользователя | Нет |
| `POST` | `/users/token` | Получить JWT access token | Нет |
| `GET` | `/users/me` | Получить текущего пользователя | Да |
| `PUT` | `/users/me` | Обновить текущего пользователя | Да |
| `DELETE` | `/users/me` | Удалить текущего пользователя | Да |

Для получения токена используется `OAuth2PasswordRequestForm`, поэтому данные передаются как form-data: `username` и `password`.

Ответ endpoint `/users/token`:

```json
{
  "access_token": "jwt-token",
  "token_type": "bearer"
}
```

## Todo

| Метод | Путь | Назначение | Авторизация |
| --- | --- | --- | --- |
| `GET` | `/todos/my` | Получить todo текущего пользователя | Да |
| `POST` | `/todos/` | Создать todo | Да |
| `PUT` | `/todos/{todo_id}` | Обновить todo | Да |
| `DELETE` | `/todos/{todo_id}` | Удалить todo | Да |

Todo создается для текущего пользователя, который определяется по JWT. При обновлении и удалении сервис проверяет владельца задачи. Если задача принадлежит другому пользователю, возвращается ошибка `403`.

## Схемы

Создание todo:

```json
{
  "title": "Подготовить отчет",
  "description": "Оформить документацию"
}
```

Обновление todo:

```json
{
  "title": "Обновленный заголовок",
  "description": "Новое описание",
  "is_completed": true
}
```

Создание пользователя:

```json
{
  "username": "oleg",
  "password": "password123"
}
```

Во входных схемах запрещены лишние поля через `extra = "forbid"`.
